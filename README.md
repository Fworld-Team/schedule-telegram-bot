# Telegram-бот расписания

[![CI](https://github.com/Fwor1d/schedule-telegram-bot/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/Fwor1d/schedule-telegram-bot/actions/workflows/ci.yml)

Код проверяется при изменении `main` и в pull request: тесты Python 3.12,
проверка секретов и runtime-данных, конфигурация, Docker-сборка и запуск
healthcheck внутри read-only контейнера.

[Последние деплои](https://github.com/Fwor1d/schedule-telegram-bot/actions/workflows/deploy.yml)
показывают commit, который CI продвинул серверу. Рабочее состояние production
смотрите через команды из [SERVER_SETUP.md](SERVER_SETUP.md).

Бот показывает расписание по кнопкам **Сегодня / Пн / Вт / Ср / Чт / Пт**,
отправляет учебный план, список экзаменов и зачётов активного семестра, карту
и сам определяет верхнюю или нижнюю неделю. Закрытая
Telegram-админка позволяет без доступа к серверу:

- создать новый семестр как черновик;
- загрузить одну общую фотографию расписания на каждый день;
- проверить заполненность и одной кнопкой активировать новый семестр;
- вернуть прежний семестр из архива;
- заполнить экзамены и зачёты для любого семестра;
- заменить карту;
- при форс-мажоре указать, что текущая неделя верхняя или нижняя.

Состояние хранится в SQLite, а фотографии — в постоянном каталоге data.
Перезапуск бота и пересборка Docker-образа эти данные не сбрасывают.

## Первый локальный запуск на Windows

1. Установите Python 3.12 с [python.org](https://www.python.org/downloads/windows/).
2. В Telegram создайте бота через @BotFather и скопируйте токен.
3. Запустите setup.bat.
4. В созданном token.txt замените заглушку токеном.
5. Запустите run.bat и отправьте боту /start.
6. Отправьте /myid и скопируйте показанный числовой Telegram ID.
7. Остановите бота, впишите ID в config.json и запустите снова:

       "admin_user_ids": [123456789]

После этого команда /admin откроет панель только вам. Для нескольких
администраторов укажите несколько чисел через запятую внутри списка.

Файлы из media/schedules и media/maps импортируются в постоянное хранилище
только при первом запуске. После этого обновляйте их через /admin.

Учебный график поставляется вместе с приложением и не импортируется в
постоянный каталог `/data`. Его файл должен быть расположен по пути
`media/study_plan/study_plan_2026_2027.png`. Пока файла нет, бот выводит
сообщение о том, что учебный график ещё не загружен.

## Работа с админ-панелью

### Новый семестр

1. /admin → **Новый семестр**.
2. Введите название.
3. Введите дату любого дня первой учебной недели.
4. Укажите, верхняя это неделя или нижняя.

Семестр создаётся как черновик и не влияет на пользователей.

### Загрузка расписания

1. /admin → **Загрузить расписание**.
2. Выберите семестр и день.
3. Пришлите общую фотографию, на которой уже есть расписание верхней и нижней
   недели, как Telegram-фото либо файл PNG, JPEG или WebP до
   10 МБ. Бот декодирует файл до замены и отклоняет повреждённые или чрезмерно
   большие по разрешению изображения.

Повторная загрузка заменяет фотографию выбранного дня. Предыдущие файлы
сохраняются в data/archive; бот оставляет последние 20 резервных замен на
семестр. Чтобы подготовить пять дней, повторите загрузку для каждого дня.

Пользователь всегда получает одно и то же общее фото дня, а в подписи бот
указывает актуальный тип недели: **верхняя** или **нижняя**.

### Активация

Откройте **Проверка**, затем **Активировать семестр**. Бот покажет покрытие
расписания по пяти учебным дням. Активация выполняется
отдельно, поэтому пользователи не увидят наполовину загруженный черновик.
Прежний активный семестр становится архивным и позже может быть возвращён той
же кнопкой.

### Экзамены и зачёты

1. `/admin` → **Экзамены и зачёты**.
2. Выберите активный, черновой или архивный семестр.
3. Добавьте дисциплину, выберите вид аттестации и укажите наличие курсовой.

Записи хранятся в SQLite с привязкой к существующему `semester_id`. Поэтому
следующий семестр можно заполнить заранее в статусе черновика: сразу после его
активации кнопка **Экзамены** начнёт показывать пользователям новый список.
Данные архивных семестров сохраняются и доступны администратору.

### Форс-мажор с неделей

/admin → **Текущая неделя** → **Сделать верхней** или **Сделать нижней**.

Это не одноразовый флажок. Бот сохраняет понедельник текущей недели как новую
опорную точку и продолжает чередование дальше:

- текущая нижняя → следующая верхняя → затем нижняя;
- текущая верхняя → следующая нижняя → затем верхняя.

Кнопка **Убрать коррекцию** удаляет коррекцию, установленную именно на текущую
неделю. После ручного сдвига слова «верхняя/нижняя» намеренно не связываются в
интерфейсе с нечётностью календарного номера: эти понятия могут разойтись.

## Команды

- /start — включить бота в текущем чате и показать меню;
- /menu — повторно показать меню, если чат уже включён;
- кнопка «Выход» — скрыть меню, сохранив уведомления;
- /stop — выключить ответы и уведомления в текущем чате;
- /today — расписание на сегодня;
- /map — карта;
- кнопка «Учебный план» — календарный учебный график 2026/2027;
- кнопка «Экзамены» — аттестации активного семестра;
- /status — публичная проверка активного расписания;
- /myid — показать числовой Telegram ID;
- /admin — закрытая админ-панель;
- /cancel — отменить незавершённую операцию в админке;
- /help — краткая справка.

Новый чат молчит до первого `/start`. Состояние каждого ЛС и каждой группы
хранится отдельно в SQLite и переживает перезапуск. В группе любой участник
может включить или выключить бота для всей группы. Когда чат активен, бот
отвечает только на команды и готовые кнопки, а обычный текст игнорирует.

## Проверка и тесты

### Тихий монитор расписания Timacad

Бот автоматически проверяет раздел **Институт экономики и управления АПК →
3 курс** для **ДЭ 23-24** и **ДЭ 24-24** раз в сутки, после 09:00 по часовому
поясу бота (production: Москва). Он каждый раз заново находит актуальную ссылку
на PDF. Ссылка с датой не зафиксирована в коде.

Уведомление приходит **только при изменении самих занятий этих групп**.
Первый запуск создаёт baseline молча. Успешная проверка без изменений, замена
PDF без изменения наших групп, повторный запуск в тот же день и технические
ошибки **не создают сообщений в Telegram**.

Получатели — существующие active chats: включённые через `/start` ЛС и группы.
`/stop` исключает текущий чат из рассылок. Отдельного списка подписчиков нет.
Если Telegram сообщает о блокировке бота или недоступном чате, он удаляется из
того же persistent-списка. Монитор только сообщает об изменениях: фотографии,
семестры и настройки админки он не заменяет.

Состояние: `BOT_DATA_DIR/schedule_monitor/state.json`, в Docker —
`/data/schedule_monitor/state.json`. Оно переживает restart, watchdog и deploy.
Подробности надёжности, ограничений доставки, парсинга и безопасного smoke test:
[docs/schedule-monitor.md](docs/schedule-monitor.md).

Проверить конфигурацию, SQLite и найденные изображения без подключения к
Telegram:

    .venv\Scripts\python.exe -m schedule_bot --check

Запустить автоматические тесты:

    test.bat

## Развёртывание на сервере через Docker

Контейнер не открывает входящие порты: Telegram long polling работает через
исходящие HTTPS-запросы. Запускайте ровно один экземпляр бота.

Для локального ручного запуска скопируйте `.env.example` в `.env`, создайте
`secrets/telegram_bot_token.txt` и выполните:

    docker compose up -d --build

Production обновляется после merge в `main`. GitHub Actions запускает CI и
продвигает проверенный commit в ветку `deploy`. Сервер раз в минуту читает эту
ветку repository-scoped ключом без права записи, собирает образ с тегом commit
SHA и переключает контейнер только после успешного healthcheck. SSH-доступ к
серверу в GitHub не хранится. Подробности первоначальной настройки и диагностики
описаны в [SERVER_SETUP.md](SERVER_SETUP.md).

SQLite, загруженные фотографии и архив находятся в Docker volume
`fworld_bot_data` и переживают пересборку. Не запускайте `docker compose down
-v`: ключ `-v` удаляет том вместе с расписанием.

Для согласованной резервной копии сначала остановите контейнер, скопируйте
каталог данных и запустите его снова:

    docker compose stop bot
    docker compose cp bot:/data ./backup-data
    docker compose start bot

Храните копию вне этого сервера.

## Если хостинг запускает Python без Docker

Нужны Python 3.12, один процесс и постоянный каталог, который не очищается при
redeploy. Установите зависимости и задайте переменные:

    python -m pip install -r requirements.txt
    ADMIN_USER_IDS=123456789
    BOT_DATA_DIR=/persistent/data
    TELEGRAM_BOT_TOKEN_FILE=/run/secrets/telegram_bot_token
    python -m schedule_bot

Точный способ задания переменных зависит от панели хостинга. Если постоянного
диска/volume нет, такой хостинг для админских загрузок не подходит.

## Безопасность и ограничения

- Доступ проверяется по неизменяемому числовому Telegram user ID и только в
  личном чате с ботом; username не используется.
- Проверка повторяется на каждой кнопке и каждом загружаемом файле.
- Токен не хранится в Git и не копируется в Docker-образ.
- Владелец чужого сервера технически может прочитать токен и данные контейнера.
  Выбирайте доверенный хостинг и храните внешние резервные копии.
- Админка исправляет расписание, карту и календарную опору, но не программные
  ошибки. Для изменения кода всё равно нужна пересборка/redeploy.
